# Security scanner upgrade decisions

## Task 1 — preserve the 0.12.0 baseline

- The application and production scanner stay at 0.12.0. Scanner source base: `b2fcb2f`; accepted Task 0 documentation commit: `3fbbedc`. No scanner rules are upgraded in Task 1.
- Benchmark implementation lives only under `benchmark/`. No application or worker module imports it. `LocalReader` structurally implements `snapshot(branch, signal)` and `blob(file, signal)` from `GitHubReader`. It hashes the current local content, enforces size/count bounds, refuses symlinks and changed blobs, and never installs or executes scanned code.
- The seeded fixture is generated locally with deterministic, publicly marked, **fake-only** credentials. Its local Git repository has two commits and no remote. A fake credential deleted in commit two is an expected history miss for the snapshot-only 0.12.0 reader. No fixture is uploaded to GitHub.
- `BENCHMARK_MODE=1` is required for fixture generation, readers, the local HTTP transport and benchmark ownership setup. It is off by default and **always rejected with `NODE_ENV=production`**, including when explicitly set to `1`. This is a separate benchmark path, not an exception added to the production SSRF guard or application ownership enforcement. The CLI uses only an ephemeral in-memory database.
- The URL adapter allows explicit local fixture hosts only, checks and pins DNS, requires same-origin redirects, and bounds response size, redirects and request time. Its direct adapter measures current HTTP analysis only (root plus at most three same-origin scripts); it does **not** represent the full browser/crawler/authenticated worker. Application URL guards and normal ownership requirements stay active even in benchmark mode.
- Docker is required for Juice Shop, NodeGoat and DVWA. If the Docker server or target is unavailable, record `not_run`, with no quality score. Their `expected/*.json` arrays are **pending annotations**, not clean negative sets. Version-specific ground truth and container validation remain pending until the images can actually run; no recall/precision is claimed for them. The supplied Compose configuration has not been runtime-validated in this environment.
- The three clean fixtures are small synthetic Next.js-shaped projects, not third-party production codebases. Ground truth explicitly treats a non-security MD5 checksum and source-authored static HTML as benign. Both trigger current heuristic false positives. This measures those known benign contexts, not general population specificity.
- Quality matching is one-to-one on category and normalized `file:line`. Duplicate findings are false positives after the first match. This is a deliberately simple location benchmark, not proof of exploitability or semantic equivalence. URLs use paths; the targets namespace locations before aggregation.
- Dependency auditing uses the real existing OSV path only when `--osv-live` is supplied. It does not substitute canned responses. When OSV cannot complete, dependency quality is **unmeasured**, with its seeded expected item retained in the expected list but excluded from measured metrics; unknown category counters are null. Both target and aggregate metrics are saved, and the report is marked partial.
- Baseline output persists metadata, category, location, rule and severity only. No evidence, code excerpt or full credential is saved. A full fake-value check fails closed before writing. JSON is serialized structurally, not passed through free-text redaction that can invalidate its syntax.
- Durations measure scanner invocation (including OSV wait when requested), excluding fixture generation, dependency installation and container startup. An unattempted target has `durationMs: null`.

## Deferred to Task 7 — automatic API origin authorization

`runAutomaticApiHttp` currently probes discovered public API origins without **per-origin ownership verification**. Existing address/network restrictions are not per-origin authorization. Task 7 will restrict probes to **verified origins or same-origin only**. This behavior is documented here and **is not changed in Task 1**. The benchmark fixtures contain no external API origin, and the local benchmark reader adapter blocks external API HTTP requests rather than generating mock scan results.

## Task 1 follow-up rulings

- Dev/holdout allocation is frozen in sourced expected manifests and `expected.lock.json`. Default development runs omit holdout files; only explicit `--final` measurements report them. These cases were seen historically in Task 1, so this is a prospective holdout. Never tune detector rules against it.
- Expected files now cite official target sources or the authored `PLANTED-ISSUES.md`; no annotations are generated from actual detector output. Docker annotations remain pending rather than being inferred from HTTP observations.
- OSV exact error diagnostics are captured in the benchmark transport, without modifying production OSV detection/parser rules. `dependency-live-attempt.json` records a real DNS EAI_AGAIN failure. Offline fixtures use the same production OSV pipeline with a documented official advisory projection and a separate reference profile. Unknown requests fail closed. Unmeasured report counts and quality are null; scorer code is unchanged.
- Docker registry references are sourced digest pins. NodeGoat's official instructions build from source rather than publish a prebuilt image; no imaginary output digest is supplied. The script verifies the published v1.4 commit prefix, uses a digest-pinned Node base, and records the resolved full source commit and locally built image ID. This is a deliberate exception to requiring a prebuilt digest for every service. Docker runtime validation and image availability cannot be certified without Docker.

## Task 2 — canonical findings with compatibility

- Existing detector modules, rule IDs, severities, pass/fail checks, scoring weights and benchmark scoreRun stay unchanged. Normalization occurs at worker progress/final persistence and exposes canonical `normalizedFindings` plus `findingNormalization.toolStatus`; a legacy-compatible view is derived for the current UI.
- Numeric canonical confidence is calibrated separately from the UI's old high/medium labels. Normalizer suppression retains findings instead of deleting them. Failed or malformed tool output is incomplete rather than a clean empty result.
- Ruling: API access matrix identities are distinct canonical locations (`URL#case=stable-id`). Without this, two principals on one resource with identical evidence collapse; the existing API matrix regression test demonstrated 4 findings becoming 2. This preserves existing detector results, and does not tune a detector or use holdout evidence.
- The pre-normalizer offline dev reference is `reference-dev-offline.json`; the corresponding after-normalizer run is `task2-dev-offline.json`. Their category metrics match exactly. Final dev+holdout reporting is run only once implementation/review are finished; any holdout miss is reported without tuning.

## Task 2.5 — precision, evidence and sealed new negatives

- Only repo.weak-hash and repo.html-sink detection logic changes. The hash rule requires a bounded local security context; non-security checksums/cache/ETags are not medium findings. HTML constants and proven default sanitizer results are accepted, while unknown mutations/provenance/context remain dynamic. Filenames and benchmark target names never influence these decisions.
- Ruling: unresolved non-JavaScript HTML context is unavailable rather than using a regex to guess whether an injected value is constant/sanitized. This avoids a false clean/vulnerable classification at the cost of needing a specialized parser for those languages. Other language/rule behavior is unchanged.
- Ruling: imported sanitizer provenance/default options are recognized; configured/unknown sanitizer semantics remain conservative. Sanitized fragments are not promoted to safe in new concatenation/attribute contexts; sanitization must cover the complete dynamic HTML.
- The real scan boundary test demonstrated a raw progress-stage filename could contain a full secret. Progress stage strings in both workers are now redacted before persistence, alongside the already normalized results. Provider fingerprints are first4+last4, while PEM/database containers and unknown opaque credential values remain fully hidden. Generic value spans are protected atomically so a token-like prefix cannot expose a remaining password tail.
- Three new negative targets were authored and sealed after an initial code freeze. Independently reproduced development-review fixes were completed before final code sealing and before either scanner evaluated the new targets. No code or target input changed after final before/after measurements. Default dev runs do not load these targets. Their results are reported separately; no tuning was performed from them.
- The old Task 2 checkout and the new frozen code were measured on the same extended final set using offline OSV fixtures and identical source snapshots. The full-set code precision changes from 44.44% to 100%; on the previously published set it changes from 66.67% to 100%. All category recalls are unchanged. Offline dependency results remain fixture integration evidence, and Docker targets remain unrun.

## Task 3 — separate scan-service foundation

- The production service is native Node HTTP/TLS plus Redis (bounded RESP client and atomic Lua queue); test-only MemoryQueue is never the production fallback. Requests are HMAC-SHA256 authenticated within ±60 seconds, source-IP restricted, schema stripped, replay protected on submit, and use fixed allowlisted tools/commands. Unknown tools reject; user args/images/limits never reach Docker.
- The dedicated non-root host controller uses rootless Docker/cgroup v2 without mounting a Docker socket in any container. Clone helpers get a per-tool internal network with a GitHub-only HTTPS CONNECT proxy; scan containers have no network. Immutable image references, resource defaults, read-only root, capability drop, no-new-privileges and input/output budgets are infrastructure constraints, not request options.
- A Linux kernel flock serializes controllers for a private tmpfs work root. Startup removes service-labelled leftover containers, their private networks, then unfinished workspaces before accepting/claiming work. Physical global/per-owner admission slots remain occupied through cleanup even after cancellation/lease expiry releases Redis slots. Cleanup failures stop admission and fail the service closed.
- Repository clone occurs inside the helper. Secret tools alone clone full history; other tools use depth 1. Git hooks, LFS, submodules, redirects and repository scripts/install are disabled. Public GitHub clone is supported by this foundation; private GitHubReader scans remain local and remote access is explicitly incomplete until a credential-safe authenticated clone path is implemented.
- Existing local scanning and scoring remain unchanged when the service is absent, invalid or unavailable. Additional tools have separate, visible incomplete metadata in the UI/API/Markdown; remote statuses use scan-service/<tool> so local OSV lookup status is not overwritten.
- Tool parsers/detection integrations are Tasks 5/6/8. Task 3 discards bounded raw output and never represents exit 0 as clean without an enabled parser. URL/Nuclei execution stays deferred to Tasks 4/8 ownership/SSRF integration. No additional active URL probe, detection rule, score weight or version changes are made here. The Task 7 automatic-origin authorization decision above is unchanged.
- Docker is unavailable in the authoring environment. Container specifications/lifecycle are tested with mocks, while the separate real Docker/Redis integration suite is NOT RUN. No fake image digest, actual isolation success or genuine tool detection result is claimed. Deployment scripts resolve real registry digests and immutable built image IDs on the user's server.

## Task 4 — unified target SSRF transport

- `resolveAndValidate` and `safeFetch` are exposed by worker/ssrf-guard.ts; the implementation reuses src/lib/network.ts IP classification, target validation, DNS deadline, pinned lookup and bounded/decompressed HTTP transport. `safeFetchPage` is the HttpPage compatibility interface, and the former requestResource name is only an alias to that guarded path.
- All DNS answers must be public and have a coherent address family. A request resolves once per hop and the HTTP/TLS connection uses the validated IP with the original Host/SNI. Redirects revalidate, with at most three hops. Existing collectors retain same-origin restrictions; HEAD/OPTIONS and API identity/proof probes retain manual/no-follow behavior. Browser redirects use CDP Fetch request-stage interception (Playwright context.route skips redirect hops), the same pinned resource transport, and a three-hop chain guard. Native browser egress stays blocked; real-browser integration is pending because Chromium startup is denied in the authoring environment.
- `runAutomaticApiHttp` STILL lacks per-origin ownership verification. Task 4 adds/reuses SSRF controls only; Task 7 will restrict it to verified origins or same-origin. Public-network validation is not ownership verification.
- Admin-configured Ollama and HMAC scan-service URLs are infrastructure endpoints, never scan-target URLs. They retain explicitly configured private/VPN access and redirect:error; project URLs, discovered origins and source content cannot replace their base URL. No public-target bypass was added for them.
- Scan-service URL execution remains deferred and scan containers remain network=none. This denies private and public network destinations independently of application validation; no future URL container may receive a bridge/host network to bypass it. Real Docker enforcement still awaits Task3 integration on the user's server.

## Task 5 — secret tools and frontend checks

- Version assumptions/pins: Gitleaks **8.24.2**, TruffleHog **3.88.23**. Upstream recorded expected JSON/JSONL examples were read at those tags; `services/scan-service/tools/fixtures/README.md` records file/blob provenance and fake-only substitutions. These are sanitized recorded-format fixtures, not locally executed tool captures. Docker/tool binaries are unavailable here.
- Parsers return only normalized locations, fixed advice, high-severity pattern indicators and first4+last4 fingerprints before results cross the parser boundary. Tool descriptions/snippets/authors/URLs/ExtraData/Redacted are not trusted or echoed. Malformed output, verified-mode TruffleHog records, process errors, timeout/truncation and cleanup failure remain incomplete. Only Gitleaks/TruffleHog lose parser_not_enabled_task3; Semgrep/OSV/Nuclei keep it/deferred states.
- A fixed trusted Node wrapper checks tool versions, scans working tree plus full Git history for repository mode, uses the pinned default Gitleaks config (MIT, blob c0c997cd04099f0be9a4e50331bd5256193725eb), ignores target ignore/inline suppression controls, and suppresses tool logs. Raw reports live only in volatile memory/tmpfs until parsing; no raw output reaches Redis/DB/API/LLM. Built secret image digests must be resolved by the server build script; none are invented here.
- TruffleHog always has --no-verification, --no-verification-cache and --no-update. The scan container remains network=none. No discovered key is used against any provider. Supabase service_role detection is local JWT payload decoding only, never JWT validation or signature verification; anon/public identifiers are not administrative secrets.
- The benchmark-only local directory/repository runner is a separate CLI/import, not an HTTP input. It requires BENCHMARK_MODE=1, refuses NODE_ENV=production unconditionally and validates symlinks/size/count before read-only network-none mounting. Default benchmarks cannot contact the configured production scan service. The existing benchmark fixture generator creates and deletes the fake history key in two temporary commits at run time; no nested .git or fixture remote is committed/pushed.
- New canonical secret results are rendered through the existing Worker normalizer and legacy report. Same-location overlaps with the old aggregate secret/public-secret findings are coalesced as one issue with multiple tool sources; every individual redacted fingerprint remains in the per-tool source ledger shown in the platform/export. This is a general source-overlap rule tested on an independent development example before final holdout measurement; no file/target-specific exception or detector/score change.
- Real Chromium redirect tests from Task4 remain NOT VERIFIED. Task3 Docker/Redis enforcement and real secret-tool detection remain pending the user's Docker-enabled server. Fixture parser success must never be presented as real history-tool recall.

Task5 final review corrections (independent dev tests, not holdout tuning):

- TruffleHog can log collection errors and still exit 0. The wrapper now captures/discards bounded JSONL stderr, enables verbosity 2 to expose Git parser failures, rejects error diagnostics and requires pinned-version completion for each pass. Exit 0 alone is insufficient. A mocked version-compatible executable reproduced the failure before the fix.
- Its Git subprocesses can drop GIT_CONFIG_* settings. Benchmark local Git config is therefore an explicit minimal allowlist; includes, worktree config, diff/fsmonitor drivers and alternate object paths are refused before a container starts. Trusted image system Git settings disable hooks/protocol egress and permit only the validated workspace ownership path.
- Canonical overlap uses the complete legacy location as well as rule/category/evidence, so URL:line detail does not create a second aggregate issue. Individual locations/fingerprints remain in the source ledger.
- NEXT_PUBLIC checks also inspect literal env-object properties and assignment RHS values; comments and string documentation remain excluded.
- Benchmark availability reporting now marks requested unavailable secret tools partial/unmeasured. This changes availability reporting only, not scoreRun, matching, weights, expectations or detection rules.

Task5 reporting boundary checks: overlap coalescing applies to secret-category findings only and cannot reclassify a code/dependency result on the same line. A sensitive NEXT_PUBLIC name with an unresolved runtime value is reported as unresolved, without inventing a credential fingerprint. Both have independent RED→GREEN development regressions; no holdout rule tuning.

Each local benchmark invocation now generates its fixtures under a unique temporary parent and removes it after scanning, preventing concurrent tests/CLI runs from mutating one shared fixture directory. Content snapshots, expected manifests and matching/scoring are unchanged. Required unavailable secret tools produce partial/null-quality reports and CLI exit 2; --secret-tools is explicitly allowlisted.
